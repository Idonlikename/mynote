    指令的基本格式¶

    指令¶

    指令的定义¶

    指的是计算机执行某种操作的命令，是计算机运行的最小操作单位。

    指令集：一台计算机的所有指令的集合。也称作指令系统。

    指令的格式¶

    一个指令包括两个部分：操作码 OP 和地址码AD。

    对于计算机而言，其回答这两个问题：干什么 ？ 对谁操作？

    按操作数区分-地址码¶

    零地址指令¶

    通常在如下两种情况中遇见：

    1. 不需要操作数。
    2. 堆栈计算机，两个操作数隐含放在栈顶和次栈顶，计算结果压回栈顶。

    解释：

    传统的计算机（比如 Intel、AMD 或 ARM 处理器）在做计算时，指令必须明确指出操作数在哪，比如：

    • ADD R1, R2, R3（意思是：把寄存器 R2 和 R3 的值相加，结果存到 R1 里）。这需要显式指定 3 个寄存器。

    而堆栈计算机不需要写这些寄存器。它的算术运算指令（比如 ADD、SUB）没有操作数后缀，它依靠一种默认的暗号，即“隐含分配”。

    例如在执行一个 ADD 指令时，直接从数据栈取顶和次栈顶，进行相加，再将结果压回栈顶。

    回忆：数据结构的后缀表达式

    一地址指令¶

    两种情况：

    1. 只需要单操作数，如++，--，取反。
    • 访存三次，取指，读A1，写A1
    1. 需要两个操作数，但是其中一个隐含在某个寄存器当中。

    如：\((ACC)OP(A_1)\rightarrow ACC\)

    访存两次，取指，读A1

    二三指令¶

    二地址指令与三地址指令，都常用于需要两个操作数进行算术运算、逻辑运算的相关指令。

    有所不同的是：

    • 二地址指令常用于，写回某个操作数的情况
    • \((A_1)OP(A_2)\rightarrow A_1\)
    • 三地址指令常用于，结果写入到一个新的操作数的情况
    • \((A_1)OP(A_2)\rightarrow A_3\)
    • 二者都需要4次访存，取指，读A1，读A2，写A3/A1

    四地址指令是在三地址指令的基础上，增加一个下一个将要执行的指令的地址。也就是PC的值修改为 \(A_4\) 所指的地址。

    也是四次访存

    按指令长度分类-操作码¶

    指令字长指的是一条指令的总长度，非固定值一般为存储字长的整数倍。

    其与IR寄存器相关

    其他的字长 定义
    机器字长 CPU进行一次整数运算所能处理的二进制数据位数（和ALU直接相关，还有通用寄存器宽度）
    存储字长 一个存储单元的二进制代码位数（和MDR位数相同）

    半字长指令，单字长字长，双字长指令。这些都是指令字长，其长度是机器字长的n倍

    指令字长会影响取指效率。如果机器字长 = 存储字长，取双字长指令则需要进行两次访存。

    指令结构和操作码¶

    定长指令字结构：指令系统中所有的指令字长相等。

    变长指令字结构：指令系统的指令字长不同。

    定长操作码：指令系统中所有指令的操作码长度

    • 优点：设计简单
    • 缺点：灵活性较差

    可变长操作码：指令系统中各指令操作码长度不同

    • 优点：灵活性强
    • 缺点：设计复杂

    扩展操作码¶

    定长指令字结构搭配可变长操作码 可以扩展操作码指令格式。在指令长度有限的前提下，保持丰富的指令种类。

    具体来说：

    以指令字长为16位，每个地址码占 4 位。

    对于三地址指令而言（只有一个操作码），那操作码仅有4位，因为全1要用作判断指令是什么地址指令。故在此共有15条指令（\(2^4 -1=15\)）。

    以此衍生，二地址指令，则是先通过前四位是否全1判断为二地址指令。同样的，八位全1要用作判断是否为一地址。

    所以三二一指令，在上述情况中，有且仅有15条指令。因为零无需给后续的指令预留全一，所以零地址有16条指令

    设计扩展操作码¶

    严格依照以下两点设计：

    1. 不允许短码是长码的前缀（哈夫曼树，前缀编码）。即短操作码不能和长操作码的前缀相同
    2. 各指令的操作码不能重复

    使用频率较高的指令，分配短操作码（加快译码速度）。不然，反之。

    在考题中，会出现计算，设置每一个地址码指令数量。然后设计操作码，一般每一个地址码的操作数不同出现冗余。冗余的量m

    和地址长度n，可以使得下一层有 \(m \times 2^n\) 种状态

    输入输出操作¶

    寻址¶

    指令寻址¶

    确定下一条指令的存放地址，也就是程序计数器 PC所存放的内容来判断下一个指令的地址。

    顺序寻址¶

    \((PC)+'1' \rightarrow PC\)

    在定长指令字结构中

    若：指令字长=存储字长=16bit=2B

    • 主存按字编址的情况，也就是PC++即可指向下一条指令。
    • 主存按字节编址的情况，那PC指向下一个指令需要+2。

    这里的按字编址指的是按照一个字长编址，而这里的按字节编址，则是以 8bit=1B 的方式编址。具体可参考第二章的边界对齐

    在变长指令字结构中

    因为在变长指令字系统中，指令字长不定，不像上述情况中存在字长前提。

    • 主存按字节编址：
    • 读入一个字，根据操作码判断指令的总字节数n
    • 以这个 n 修改PC的值

    跳跃寻址¶

    跳跃指令本质上顺序寻址的改良，在指令的执行过程中插入一个转移指令 JMP 确定下一个指令的位置。

    在定长指令字结果沟中

    若：指令字长，存储字长，均为16bit

    • 依旧使用PC+‘1’的方式，进行某一组指令
    • 在完成之后，继续跳转到下一个指令，跳转指令JMP将其跳转到一个新指令处。
    • 本质是直接改变了PC的值

    还有 CALL 也是跳跃寻址

    数据寻址¶

    确定本条指令的地址码所指明的形式地址，如何转化为操作数的真实物理地址（有效地址，Effective Address, EA）。

    原先：操作码OP|地址码AD

    采用形式地址： 操作码OP|寻址特征(四位二进制决定何种方式寻址)|形式地址

    前置格式暗号：数据寻址的指令格式中，地址码部分通常被拆分为 | 寻址特征 | 形式地址 A |。

    • 寻址特征：告诉 CPU 应该用哪种寻址方式（比如查表、加寄存器等）。
    • 形式地址 A：指令字面上的数值，不一定是最终的数，也不一定是最终的内存地址。

    上述形式针对一地址指令。

    若针对多地址指令，以二地址为例：

    • 操作码OP|寻址特征|形式地址|寻址特征|形式地址
    • 给每一个形式地址添加寻址特征
    • 可见多地址指令中的地址的寻址方式并不唯一

    \(EA\) 是有效地址（Effective Address）

    基础寻址方式¶

    直接寻址¶
    • 定义：形式地址 \(A\) 即为真正地址。
    • 硬件特性：\(EA = A\)。
    • 访存次数：2次（取指1次，读数据1次）。
    • 优点：简单，不需要做复杂的地址计算。
    • 缺点：\(A\) 的位数决定了该指令只能访问局部的内存空间（如 \(A\) 占4位，只能访问16个单元）。
    间接寻址¶
    • 定义：形式地址 \(A\) 指向的内存单元里，装的是操作数的有效地址 （即“套娃/指路牌”）。
    • 硬件特性：\(EA = (A)\)（一次间寻）；或者 \(EA = ((A))\)（多次间寻，看存储字首位是否为1判断是否继续套娃）。
    • 访存次数：3次及以上（取指1次，读有效地址1次，读数据1次）。
    • 优点：扩大了寻址范围（可以用短 \(A\) 访问大内存），便于编制程序（如方便实现动态跳转或指针）。
    • 缺点：多次访存，速度极慢。
    寄存器寻址¶
    • 定义：操作数不在内存里，而是放在 CPU 内部的通用寄存器中。形式地址 \(A\) 给出的是寄存器编号 \(R_i\)。
    • 硬件特性：\(EA = R_i\)。
    • 访存次数：1次（取指1次，执行阶段0次访存）。
    • 优点：执行速度极快，且寄存器数量少，寄存器编号占用的地址码位数极短（省指令空间）。
    • 缺点：寄存器硬件成本高，数量有限。
    寄存器间接寻址¶
    • 定义：寄存器 \(R_i\) 里面装的不是数值，而是操作数在内存中的真正物理地址。
    • 硬件特性：\(EA = (R_i)\)。
    • 访存次数：2次（取指1次，去内存读数据1次）。
    • 大白话考点：兼具寄存器寻址省地址码空间的好处，又能像间接寻址一样访问大内存，且比内存间接寻址少访存一次，408考题中最常用的寻址方式之一。
    隐含寻址¶
    • 定义：操作数的地址不显式地写在指令中，而是由操作码隐含指明。
    • 举例：一地址加法指令中，另一个操作数隐含在 \(ACC\)（累加寄存器）中。
    • 硬件特性：\(A \rightarrow ALU\)，同时 \((ACC) \rightarrow ALU\)。
    • 优点：缩短指令字长，省地址码空间。
    • 缺点：灵活性差。
    立即寻址¶
    • 定义：形式地址 \(A\) 根本不是地址，它就是操作数本身（一般用补码表示，考题中常带有 # 符号）。又称作立即数
    • 硬件特性：有效地址 \(EA\) 无定义。指令直接把 \(A\) 送进 \(ALU\)。
    • 访存次数：1次（取指阶段访存，执行阶段0次访存）。
    • 优点：执行速度最快（不用再去内存捞数）。
    • 缺点：\(A\) 的位数限制了操作数的范围，且改代码不方便。

    偏移寻址¶

    偏移寻址的通用本质公式为：

    (\(EA = \text{某个特定寄存器的内容} + \text{形式地址 } A\)\)

    基址寻址（Base Address Register）¶
    • 公式：\(EA = (BR) + A\) （\(BR\) 为基址寄存器，或指定通用寄存器）。
    • 核心规定：\(BR\) 的内容由操作系统（OS）或特权指令决定，程序运行期间其值不可变；而形式地址 \(A\) 可变。
    • 大白话物理图像：把 \(BR\) 看作整栋楼的“一楼大门口基准线”，\(A\) 是“往上走几层”。
    • 作用（考试必考原因）：
    • 扩大寻址范围（\(BR\) 位数通常很长，可以指到极深处的内存）。
    • 有利于多道程序设计和程序的动态重定位。程序不管被整体搬到内存的哪个角落，只需要改一下 \(BR\) 的初始值，代码里的 \(A\) 完全不用改，就能直接顺序运行。

    在没有 \(BR\) 的情况下，以通用寄存器作为基址寄存器使用，在指令侧，需要指明所用的通用寄存器。注意这里的\(R_0\)不是直接指明了寄存器是哪个，还是通过二进制方式指出是哪个寄存器。

    采用通用寄存器的时候，用户决定寄存器为基址寄存器，内容仍然由操作系统规定。

    变址寻址（Index Register）¶
    • 公式：\(EA = (IX) + A\) （\(IX\) 为变址寄存器）。
    • 核心规定：\(IX\) 的内容由用户/程序员决定，程序运行期间其值频繁自动改变（如 \(IX++\)）；而形式地址 \(A\) 作为基准首地址，不可变。 \(IX\) 可以视作偏移量

    • 大白话物理图像：\(A\) 是数组的首地址（如 array[0] 的位置），\(IX\) 是循环里的下标 i。

    • c for (int i = 0 ; i < 10; i++){ sum += a[i] }

    • 作用（回忆数据结构）：

    • 专门为了高效处理“循环结构”和“数组/线性表遍历”而生。

    • 配合跳跃寻址使用：每次循环结束前，硬件或指令自动给 \(IX\) 加1，PC 再 JMP 回去，就能极其丝滑地顺序访问整个数组。
    相对寻址¶

    • 公式：\(EA = (PC) + A\) （针对当前程序计数器 \(PC\) 做的偏移）。

    • 核心规定：有效地址是基于当前 PC 值的相对位移。

    • 必考计算题：

    当 CPU 从内存中取出一条相对寻址的指令后，还未开始执行，PC 已经自动执行了顺序寻址的加步长操作（即 \(PC \leftarrow PC + \text{指令字长}\)）。

    所以，计算真实的 \(EA\) 时，代入的 \((PC)\) 必须是“执行该跳转/寻址时，已经顺延指向下一条指令的那个新PC值”。

    • 作用：

    • 专门为了“跳跃寻址（JMP/分支跳转）”而生。

    • 使得代码在内存中具有程序局部浮动性（无论整段代码搬到内存哪里，由于跳转指令和目标指令的相对距离 \(A\) 没变，代码依然能精准跳转）。

    堆栈寻址¶

    操作数放置于堆栈中，隐含使用堆栈指针 \(SP\) 作为操作数地址。\(SP-Stack\ Pointer\)

    • 公式：\(EA = SP\)
    • 分类与执行流（结合数据结构复习）：
    • 硬堆栈：CPU 内部有专门的寄存器串联成的栈（速度快，容量小）。
    • 软堆栈：在主存中强行划出一块特定区域作为堆栈区（最常用）。
    • 入栈（PUSH）与出栈（POP）的微操作时序（408高频选择题）：
    • 假设栈从大地址向小地址生长（往低地址压栈）：
      • PUSH 过程：\((SP) - 1 \rightarrow SP\)，然后将数据写入 \((SP)\) 所指单元。（先动指针，后写数据）
      • POP 过程：先从 \((SP)\) 所指单元读出数据，然后 \((SP) + 1 \rightarrow SP\)。（先读数据，后动指针）
    • 与零地址指令串联：回到本章开头，堆栈计算机执行 ADD 时，无需显式地址，底层逻辑正是隐含地进行两次 \(SP\) 出栈，ALU 算完后再次根据 \(SP\) 指针执行入栈。

    数据寻址方式¶

    寻址方式 有效地址 EA 公式 访存次数（不含取指） 核心解决什么问题（一句话）
    立即寻址 无定义（\(A\) 就是操作数） 0 最求极限速度，用于常量赋值
    直接寻址 \(EA = A\) 1 最简单的内存访问
    间接寻址 \(EA = (A)\) 2次及以上 解决扩大寻址范围和指针问题
    寄存器寻址 \(EA = R_i\) 0 榨干速度，数放在 CPU 肚子里
    寄存器间寻 \(EA = (R_i)\) 1 高效访存的折中王牌，指针的底层
    基址寻址 \(EA = (BR) + A\) 1 操作系统管的，解决程序整体搬家（重定位）
    变址寻址 \(EA = (IX) + A\) 1 程序员管的，专门用于数组和循环遍历
    相对寻址 \(EA = (\text{更新后的}PC) + A\) 1 解决代码局部内跳转（if/while）
    堆栈寻址 \(EA = SP\) 1 零地址指令、函数嵌套与表达式求值

    JMP的形式多样。

    • JMP 128 可以用 [常数] 跳转到地址，
    • JMP eax，也可以用寄存器
    • JMP [999]，地址也可以来自于主存。
    • JMP NEXT，也可以用标号锚定。

    条件转移¶

    循环语句¶

    可以用条件转移实现循环。用四个部分构成：

    1. 循环前初始化
    2. 用条件转移判断是否直接跳过
    3. 循环主语句
    4. 是否继续循环
    GAS
    # 初始化
mov eax,0
mov edx,1
# 第一次判断
cmp edx,100
jg L2
# 循环主体
L1:
add eax, edx
inc edx   # 自增
# 是否继续循环 
cpm edx,100
jle L1
L2:

    loop指令执行¶

    指定使用 ecx 作为循环计数器。整体结构如下

    GAS
    mov ecx,500
Looptop:  # 循环开始

....

loop Looptop

    loop Looptop 本质等价于

    GAS
    dec ecx # ecx -- 
cmp ecx,0
jne Looptop

    采用loop指令的情况下，所用的寄存器一定是ecx，不能用其他寄存器。

    loop的意义：尽管我们可以用条件跳转实现等价的循环，但loop的好处还是其更为简洁。

    函数调用¶

    在进行函数调用的时候，系统会为程序分配一个函数调用栈

    在程序调用一次函数后，就会把函数的栈帧压入到栈区，直到函数return之后，才会被弹出栈区。

    所以在多个函数调用所组成的程序中（调用中包含调用，包括递归）

    不断调用会将栈帧不断压入栈区（栈区会不断生长，向着低地址生长。）

    而最新调用的函数一定是最先return的，也就是栈顶弹出

    栈帧 Stake Frame：保存函数大括号内定义的局部变量、函数的调用相关信息

    调用指令 call 返回指令 ret

    GAS
    caller: # 用函数名作为标号置于函数开始
···· # 一系列初始化和操作
call add # 调用另一个函数
····
ret # 返回，结束调用

    call指令的作用：

    • 将IP旧值压栈保存（保存在当前栈帧顶部）
    • 设置IP新值，无条件跳转至被调用函数的第一条指令

    ret指令：

    • 从函数栈帧的顶部找到IP旧值，将其出栈并恢复IP寄存器

    访问栈帧里的数据¶

    ebp：指向了栈帧的底部

    esp：指向了栈帧的顶部

    方法一：¶

    在x86系统中，默认都是以 4byte 作为栈的操作单位：

    • 所以栈帧是以4字节作为基本存储单位的
    • Pop和Push两个栈操作也是以4字节作为基本操作单位
    • Push的操作数可以是立即数、寄存器、主存地址
    • Pop的操作数可以是寄存器、主存地址（少一个立即数）

    注意：pop后面跟的操作数，是用来存储弹出数据的地址

    push 和 pop的这种差距的原因是：

    push是将数据压入栈区，数据的来源可以是立即数，也可以是地址的数据

    而Pop是将栈区的数据弹出，数据存储到操作数中，所以操作数应该是一个地址

    方法二：¶

    用mov指令，结合esp、ebp指针访问栈帧数据

    采用加减法指令，修改栈顶esp的值。

    切换栈帧¶

    执行Call指令的时候：¶
    • IP旧值压入栈中，压在当前的栈帧的栈顶（被视作当前栈帧的一部分，而非被调用栈帧的一部分）。
    • 设置IP的新值，无条件跳转到被调用函数的第一条指令

    对于 esp和 ebp 而言：

    • 首先将 ebp 的地址信息push到栈顶

    • 再将 esp的值赋值给ebp

    GAS
    push ebp
mov ebp esp

    这两行指令等价于enter，enter无需任何操作数。

    • 也就是栈帧底部存储函数信息前，存储了IP旧值和上一个函数的栈帧基址

    可见栈帧的底部，存储的内容都是上一个函数栈帧的基址。esp的值不需要管，有东西push进栈，CPU中自然会给其更新。

    执行ret指令的时候：¶
    • 让esp达到目前基址，再将栈顶的值弹出存入ebp
    GAS
    mov esp,ebp
pop ebp

    在栈帧中ebp作为寄存器，其本身存储的就是当前栈帧的基址。（存储的是地址编码）

    而当前栈帧的基址存储着上一个栈帧的基址

    这也是为什么，让ebp成为栈顶后，弹出的信息可以让ebp再次指向上一个基址。

    这两条指令等价于 leave，也无需操作数

    • 最后，从当前栈顶 esp找到IP旧值，恢复到IP寄存器

    栈帧包含的内容¶

    • 栈底是上一个栈帧的基址
    • 栈顶是IP旧值

    最靠近栈底的部分是局部变量。不一定存在

    • 访问当前函数的局部变量通常采用，[ebp - a]

    最靠近栈顶的部分是调用参数，不一定存在，有些函数调用不需要传参。同时这个调用参数，是给这个函数所调用的函数使用的。

    • 访问当前函数的调用参数，通常采用 [ebp + a] 存储在在上个函数当中。
    C++
    int main(){
    int a = 10;
    int b = 5;   // 这里的a b就是局部变量
    add(a,b);  // 这里的a b就是调用参数
}

    gcc编译器，将每个栈帧的大小设置为16B的整数倍（当前的函数栈帧除外）

    CISC和RISC¶

    复杂指令集和精简指令集。

    80-20规律：程序中80%的语句仅仅使用了20%的指令（CISC）。也就是20%的CISC指令是常用的。

    乘法指令可以访存，一定是CISC（即同时完成访存和乘运算的指令）

    RISC仅含Load和Store是无法做到的。
