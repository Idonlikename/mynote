    查找¶

    Algorithm¶

    ASL(Average Search Length)¶

    ASL指的是平均查找长度，一次查找长度是指需要比较的关键字次数。与之后的查找长度需要区分。

    在查找过程中，查找长度指的是需要比较关键字次数，而平均查找长度则是所有查找过程中进行关键字的比较次数的平均值。

    其中\(P_i\) 指的是查找第 \(i\) 个元素的概率，\(C_i\) 则是比较的关键字次数 $$ ASL = \sum_{i=1}^{n}P_iC_i $$ 通常我们讨论考虑的时候，延伸出来的还有ASL成功，和ASL不成功，即查找成功时的平均查找长度和查找失败时的平均查找长度。 $$ ASL_{成功}= $$

    顺序查找¶

    也称作线性查找，对于顺序表和链表均友好的一种查找。

    折半查找¶

    也就是二分查找，适用于顺序表查找且顺序表内的数据需有序，因为依靠下标 mid 进行查找，而链表不能随机存取 。需要注意的地方是用mid更新left 和 right

    C++
    right = mid - 1;
left = mid + 1;

    所得的树高为： $\lceil{log_2(n+1)}\rceil $

    DataStructure¶

    本节主要介绍用于查找的数据结构，特指用于查找的二叉树。

    查找长度( Search Length)¶

    指的是在查找运算中，需要比对的关键字次数。反映了查找操作的时间复杂度

    相比较平均查找长度，无需考虑每个数据被查找的概率。 $$ SL = \sum_{i=1}^n C_i $$

    二叉排序树——BST¶

    二叉排序树又称二叉搜索树——BST（Binary Search Tree）

    构造二叉排序树的目的是为了 增删改查。

    跟二分查找一样理解。但作为一种数据结构，需要学习和理解其结构的操作。

    对于其插入，改（查）实际是很简单的，只需要注意：二叉排序树因为结构是 左子树的结点值<根结点值<右子树结点值 所以其采用中序遍历，从而实现了有序遍历。

    而比较特殊的是二叉排序树的删除操作中的删除一个“根结点” 即一个既有右子树和左子树的结点（若是只有其一，让其子树父结点代替即可），需要选取其右子树的最左下的结点（或者是左子树的最右下结点）。本质上，是为了维护这种有序遍历，必须让中序遍历中的直接前驱 或者 直接后继 来代替这个结点。

    平衡二叉树——AVL Tree¶

    定义

    平衡二叉树指的是任意结点的左右子树高度差绝对值不超过1 的二叉树。平衡二叉树也称作 AVL树。

    作用

    在此处平衡二叉树的作用是避免树的高度增长过快，降低二叉排序树的性能（由此可得一点，当左右子树的高度差增加，二叉排序树的性能会下降）。

    空树 \(\empty\) 也是平衡二叉树。

    补充定义： 定义某个结点的左子树和右子树高度差为该结点的平衡因子，平衡因子 = 左子树高 - 右子树高，根据平衡二叉树的定义则平衡二叉树的平衡因子只能使1，0，-1。

    操作¶

    插入¶

    维护平衡：每当二叉排序树插入一个结点，首先检查是否会因为本次插入导致不平衡。若导致了不平衡，则将离插入结点最近的平衡因子绝对值大于1的结点A，调整结点A的的子树。

    这个以结点A为根的子树我们称作最小不平衡子树。只需将最小不平衡子树调整平衡，其他祖先结点的平衡因子自然符合条件。而最小不平衡子树是我们的最小操作单位。

    我们考虑四种情况进行维护：

    • LL ：以LL为例，表示在A的左孩子的左子树中插入导致不平衡
    • RR
    • RL
    • LR

    依旧LL为例：在A的左孩子的左子树插入导致不平衡。为了方便讲解，将以下A的左孩子称作B结点

    假设所有子树的高度为H，指的是B的左右子树和A的右子树。经过检验这样假设既满足根节点A再插入前是平衡的，其他结点在插入前也是平衡的，也满足了在插入后，A是最小不平衡子树的根结点。注意：A在插入前的平衡因子就已经是1了；

    维护操作 case1

    操作最小不平衡子树的左右子树

    对于LL的情况，将B替代A成为这个树的根结点，而A成为其右子树。需要额外注意的一步：将B的右子树，变为A的左子树，因为此时A是左孩子的右孩子。保证继续满足二叉树定义和二叉排序树的 左子树结点值<根结点<右子树结点值 。 这个操作称作右旋B。

    RR因为和LL都是边缘的树导致的不平衡，二者实际同理。无非是对于RR注意右孩子，即A的右孩子为B结点，在RR的情况中我们进行的是左旋B

    以上LL RR进行的旋转操作称作单旋，我们只对最小不平衡子树的根的子结点B操作

    Text Only
         A               B
    /  \           /   \
   B    H   ->   H+1    A (H+1)
  / \                  / \
H+1  H                H   H

    维护操作 case2

    操作最小不平衡子树的左右子树的子树。

    而LR和RL的树是因为中间子树的树高导致的不平衡，无法通过边缘子树的抬高，即抬高被插入的边缘子树的父结点B来实现平衡，需要重新考虑。引入B的对应的孩子结点，结点C。我们同样设B的左右子树和A的右子树的高度为H，因为这仍是最符合我们假设的情况。不过需要注意的是，对于RL和LR而言，其插入C结点的左子树或右子树均有可能。

    在这种状况下：C的子树的高度应为 \(H-1\) 而插入一个之后其中某个子树会变成 \(H\) 我们需要做的就是把这个子树尽可能拉高

    直接给结论：对于RL和LR这类特殊情况，先左旋C再右旋C（对于RL则是先右旋C再左旋C，本质是先跟B换位置再跟A换），每一个旋的目的都是为了抵消对应的LR，如RL我们先右旋，目的是为了抵消RL当中的L，这是一个类似于栈的抵消，对于最后一个产生的操作是我们最先要抵消的。

    下面给一个样例LR

    Text Only
         A                  A                     C
    /  \               / \                 /     \
   B    H        (H+2)C   H               B(H+1)  A (H+1)
  / \         ->     / \        ->       / \     / \    
 H   C              B   H-1             H   H  H-1  H
    / \            / \
   H  H-1         H   H

    小结：

    左旋：①操作的结点作为右结点（与操作方向相反）代替其父结点，而父结点作为结点的左结点 ②将其左子树变为父结点的右子树。

    右旋：①操作的结点作为左结点代替其父结点，而父结点作为结点的右结点 ②将其右子树变为父结点的左子树。

    回顾一下整个插入：

    1. 找到对应位置插入
    2. 进行检查是否不平衡——找最小平衡子树。由插入结点开始向上传导查找
    3. 找到最小不平衡子树，开始操作使其平衡。考虑四种维护平衡情况 - LL - RR - LR （和RL一块需要C） - RL

    查找效率：平衡二叉树的平均查找长度为 \(O(log_2n)\) ，最大深度也为\(O(log_2n)\)

    删除¶

    删除步骤：

    1. 删除结点判断 - 是叶结点，则直接删除 - 只有一个子树，则由子树替代 - 有两个子树，用中序遍历的直接前驱和直接后继结点替代。对删除结点的值复制为直接前驱或后继的值，转为对这个前驱和后继的删除。重复删除结点判断，直到是前两种情况。
    2. 向上搜寻最小不平衡子树。也就是判断是否不平衡。
    3. 若有最小不平衡子树，则找①最小不平衡子树下的最高子树B，以及②最高子树的最高子树C
    4. 根据C的位置进行 LR RL LL RR 判断调整平衡
    5. 继续向上传导继续 2

    • 相较于插入操作，平衡二叉树的删除操作，除最开始的找到结点位置由插入改为删除外。它比插入步骤多一步（3可以并入4）： 5. 由于删除操作可能导致不平衡传导，需要继续检查，重复上述由2~3的步骤

    • 相较于插入操作，删除操作在第3步中，不是直接找到最小平衡树的对应左右子树。

    而是找到①最小不平衡子树下的最高子树，以及②最高子树的最高子树

    如果最高子树的最高子树在LL，我们则直接对最高子树进行右单旋B（B指代最高子树的根结点，同理C指代最高子树的最高子树的根结点）

    • 此处的LL RR LR RL不再是插入结点的位置，而是最高子树的最高子树即C对于最小不平衡子树的根结点的相对位置。RR同理，对最高子树进行左旋，即左单旋B。操作的是B同样是操作最小不平衡子树的左右孩子结点，只是考虑高度；LR和RL则是对C结点进行操作，和插入操作中相似的，LR则对C结点进行先左旋再右旋；RL则对C先右旋再左旋

    红黑树-RBT¶

    目的

    在前面部分，为了保持AVLT（平衡二叉树）的平衡性，插入和删除之后需要频繁调整整体的拓扑结构，开销很大。因而在平衡上放宽，引入了红黑特性。

    定义：

    红黑树是一种二叉排序树（左子树结点值<根结点值<右子树结点值）

    相较于平衡二叉树在查找上具备优良性能，红黑树则是在插入删除上具备优良的性能。

    红黑特性定义：

    ①. 每个节点是红色或黑色。

    ②. 根结点为黑色

    ③. 每个叶结点（NULL，空结点）是黑色

    ④. 不存在相邻的红结点——红结点的子结点与父结点都是黑色

    ⑤. 对于每个结点，从该结点到任意叶结点的简单路径——路径上没有重复的结点上，经过的黑结点数目相同。黑高一致

    黑高：经过黑结点的数目，注意是经过，所以不包括该结点本身。

    由定义产生的性质¶

    1. 从根到叶的最长路径不大于最短路径的两倍（考虑最长路径在黑结点之间穿插红结点，而最短路径不穿插，而首尾都是黑结点）
    2. 有n个内部结点（非叶结点，叶结点在红黑树中称作外部结点）的红黑树高度 \(h \le 2log_2(n+1)\) - 由此可得红黑树的查找效率应为 $ O(log_2n)$ - 已知根结点黑高为h，则红黑树至少有 \(2^h-1\) 个内部结点（考虑没有红色结点） - 由上述第二点，逆推 $2^h-1 \leq n \implies 2^h \le n+1 \implies h \leq log_2(n+1) $

    操作¶

    红黑树的查找与BST AVL均一致，按照二分查找的方法，大于当前结点的值则找右孩子结点，反之找左孩子结点。若找到叶结点，则查找失败。

    插入¶

    插入效率为 \(O(log_2n)\)

    步骤一：按 BST 规则插入节点

    • 将新节点当作红色插入（红色更容易满足性质5，必要时可调整）。

    步骤二：检查红黑性质，进行修复（Insert Fix-Up）

    1. 新节点是红色，若其父节点也是红色，则破坏了性质4；
    2. 则需要进行重新着色和/或旋转操作来恢复红黑性质。

    着重强调插入修复操作：

    case1¶

    叔叔结点是红色——则只需着色，但需要递归检查

    • 将父结点 p 和叔叔结点 u 变黑；
    • 将祖父结点 g 变红；
    • 把祖父结点 g 当新插入节点，继续向上调整；如果无上，将祖父结点变黑（递归）。

    理解：父结点和子结点冲突，所以需要改色父结点，同时为了维持黑高，需要把祖父结点的黑继承给uncle 和 parent。如果祖父结点是整个树的根结点，则直接染黑，全部黑高+1；

    case2¶

    主要操作插入结点的父结点

    叔叔结点是黑色，且插入到“外侧”——旋转+着色（让父结点和祖父结点互换，颜色和位置）

    • 以 g 为根节点做单旋转，旋转方向依据将父结点转为根。
    • 再将父结点 p 着黑，祖父结点 g 着红。（父结点原来是红，变根转黑，祖结点变红稳定黑高）
    case3¶

    操作插入结点

    叔叔结点是黑色，且插入到“内侧”（通常叔叔结点是叶结点）

    • 对插入结点做双旋，即将子结点变为爷结点位置，并且爷结点和子结点互换颜色

    小结：case2和case3如同 AVL当中的情况，判断情况内侧（LR,RL）外侧（LL,RR）对B（父结点）进行单旋，C（插入结点）进行双旋。只是红黑树多一个操作结点和爷结点呼唤颜色的步骤

    删除¶

    效率同样为 \(O(log_2n)\)

    B树¶

    在引入B树前，先以研究M叉树作为背景。

    M叉树¶

    M叉树，最多有m个分支以及m-1个关键字，关键字-key 就是用于比对大小的value。

    提高查找效率¶

    分支和关键字策略：如果关键字太少，会导致树高增大，使得层数变多，查找效率下降。所以为了保证查找效率，规定m叉查找树中，除根结点以外的结点至少有 $ \lceil m/2\rceil$ 个分支与 \(\lceil m/2 \rceil -1\)个关键字 。

    • 因为出现一个结点的情况，根结点只能有一个关键字和两个分支，所以对根结点不作同样的要求。

    高度策略：参考平衡二叉树部分，平衡因子过大会导致查找层数增加。因而规定包括根结点在内的任何一个结点，其所有子树的高度相同，即任意结点的平衡因子为 0 。

    满足高度策略和分支关键字策略的m叉树则是B树。

    B树，又称作多路平衡查找树，B树中所有结点的孩子个数的最大值 $ V_{max} $ 称为B树的阶，用 \(m\)表示。也就是分支的最大值

    一棵m阶树B树：

    • 要么是 \(\emptyset\)
    • 要么是满足下列性质的m叉树：
    • 每个结点至多有m棵子树，因而有\(m-1\)个关键字（一个关键字有两个子树）
    • 若根结点不是终端结点（无子结点的结点），则至少有两棵子树（高度策略，保证根结点绝对平衡）
    • 除根结点以外的结点至少有 $ \lceil m/2\rceil$ 个分支与 \(\lceil m/2 \rceil -1\)个关键字
    • 所有叶结点都在同一层次，且无信息（NULL）意味着查找失败的结点。（高度策略）

    tips性质可以归为如下：

    • 根结点子树\(\in[2,m]\)， 关键字\(\in[1,m-1]\)。其他结点子树\(\in[\lceil m/2 \rceil,m]\)，关键字\(\in[\lceil m/2 \rceil-1,m-1]\)
    • 对任意结点，所有子树高度相同，树高并不涵盖叶结点（失败结点）
    • 关键字的值，左<中<右

    B树若有n个关键字则总共会有n+1叶结点。可以想象对于\((-\infin,+\infin)\) 切了n刀，共计有\(n+1\)端。即有\(n+1\)个失败结点。

    对于B树因为除根结点以外都有\(\lceil m/2 \rceil\)个分支，所以当有h的高度，则第h层至少有 \(2\lceil m/2 \rceil ^{h-2}\) 个结点，可得叶结点至少有(2\lceil m/2 \rceil ^{h-1} \(个结点，而可得\)2\lceil m/2 \rceil ^{h-1}\le n+1\) 。 由此也可以推出 $ h \le log_{\lceil m/2 \rceil}{\frac{n+1}{2}} +1$

    插入¶

    对于一个新元素（关键字），将其插入到终端结点，而当结点数量超出了一个结点的关键字最大值\(\in [\lceil m/2 \rceil -1 ,m-1]\)。则会进行分裂。

    分裂是B树插入操作的要点：

    • 向上分裂，取结点的中间结关键字（向上取整）作为父结点而切割出两个结点。
    • 若有父结点且父结点未满则加入到父结点。
    • 若父结点已满，则对父结点重复上述操作

    这也就是为什么，根结点允许只有一个关键字两个子树，向上生长的过程中，一个关键字作为父结点分裂，而这个父结点只有这一个关键字。

    删除¶

    对于删除的元素（关键字）。所讨论情况均为删除元素后结点关键字不足：

    我们都采取直接删除找寻元素替代的方式。

    • 若删除非终端结点关键字：则直接前驱或直接后驱来替代，即被删关键字的左（右）指针所指子树的最右下（左下）元素。
    • 若删除的是终端结点关键字：
    • 前提：左（右）兄弟结点的元素充足（\(> m/2\)）。取当前结点和兄弟结点的之间的父结点关键字进行补充，而父结点由兄弟结点补齐（具体情况：右兄弟充裕，则补其最小元素至父结点，左兄弟充裕补最大元素至父结点）
    • 前提：兄弟节点元素不足（\(=m/2\)）。则取兄弟结点和二者之间父结点关键字一起组成新结点（合并），具体情况同上。
    • 补充：在第二个情况中，可能会导致父结点取完关键字再次关键字不足，则重复上述操作。

    B+树¶

    B+树（B+ Tree）是一种常用的树形数据结构，广泛应用于数据库和文件系统中（如 MySQL 的 InnoDB 引擎、NTFS 文件系统），用于高效地存储、检索和维护大量数据。它是 B 树的变种，优化了查询性能和存储效率。B+Tree的目的是为了增强查找效率，所以其叶结点均会指向一个记录，所以每次查找操作都会找到叶结点（叶结点才有指向记录的指针）。

    定义：

    • 每个分支节点最多有m棵子树
    • 非叶根结点至少有两个子树，其他每个分支结点至少有\([m/2]\)棵子树（同B树）
    • 结点子树个数与关键字个数相同（B+树的分支即为关键字。而非用关键字切割作为分支）
    • 所有叶结点包含全部关键字和指向相应记录的指针，叶结点中将关键字按大小顺序排列，并且相邻叶结点按大小顺序相互链接（支持顺序查找）
    • 所有分支结点中仅包含他的各个子结点（下一级索引块）中关键字最大值和指向其子结点的指针。（所以相较于B树，B+树的分支结点的每个关键字均是其对应的结点的最大值）

    本质上：B+树是为了提高查询效率，而提高树的查询效率最有效的方式就是降低树高，也就是需要每一个结点（实际中，如磁盘空间的I/O基本单位。称作块）所容纳的关键字足够多树才足够矮，而B树这种每个结点的关键字都有对应信息的方式，导致一个结点中不单有关键字还有指向信息的指针，导致一个结点（块）所容纳的关键字不够多，而B+树则是通过让每一个结点（块，且每个块大小有限制）包含尽可能多的关键字，由叶结点来包含指针指向记录。

    散列表——Hash Table¶

    哈希表，是一种可以给根据数据元素的关键字，计算出它在散列中的存储位置。

    C++
    unordered_map <int,int> hash;
// 一种由int作为关键字，同时作为的value的无序散列表

    概念¶

    散列函数（哈希函数）

    一个把查找表中的关键字映射成该关键字对应地址的函数。记为：Hash(key) = Addr

    hash表是一种查询效率很高的数据结构，效率为 \(O(1)\)

    冲突（碰撞）

    将两个或两个以上的不同关键字映射到同一地址。这些发生冲突的值称为 同义词

    散列函数¶

    之前提及了“冲突”。学习散列表的目的，主要是减少冲突和处理冲突。而一个优秀的散列函数，需要尽可能减少冲突的发生。

    对于一个标准散列函数，需要满足以下要点：

    • 定义域涵盖所有可能出现的关键字 （定义域）
    • 值域不能超出散列的地址范围 （值域）
    • 尽可能减少冲突的发生，函数计算出的地址要尽可能均匀分布在整个地址空间。(尽可能双射)
    • 散列函数需要尽量简单，能够快速计算 （function）

    除留余数——最常用

    \(H(key) = key \bmod p\) $ p $需为质数/素数。（只能被1和其本身整除的数）

    关键在于质数的取值，假设表长\(m\)，则取不大于\(m\)但尽可能接近或等于\(m\)的值为\(p\)

    适用场景：关键字为整数即可。

    直接定址

    $ H(key) = key or H(key) = a*key +b$ （线性组合直接取址）

    优势：a和b均为常数，简单易算，且不会发生冲突。

    劣势：若关键字分布不连续，导致存储空间浪费。

    适用场景：关键字基本连续分布

    数字分析

    选取数码分布较为均匀的若干位作为散列地址。

    较难理解：简单点说，对于一组整数关键字来说，也许他们本身之间是不够连续的。但是，可以采取取每个数当中几位的方式，使得关键字足够连续。

    适用场景：关键字集已知，且关键字当中某几位数码分布均匀。

    平方取中

    顾名思义：取关键字的平方值的中间几位作为散列地址。具体取多少位要视情况而定

    因为这种方式得到的散列地址与关键字的每位（平方，每一位都与其他位和它本身相乘）都有关系，因此散列分布比较均匀。

    适用场景：关键字每位取值都不够均匀。

    全然，一个散列函数设计得再出色，无法避免会发生地仍可能会发生冲突，所以学习如何处理冲突仍然是很重要的。

    冲突处理¶

    拉链法¶

    将所有“同义词”存储在一个链表中的方法。尾插还是头插视情况而定（默认头插）。

    优化

    若采用单纯的头插法或者尾插法，链表并不有序。可以通过保证链表有序，从而提高查找效率。

    开放定址法¶

    即，发生冲突时，则给新元素从初始散列地址开始，探寻另一个空闲位置。

    问题的关键在于：这个另外的空闲位置应在何位置？

    采用如下方法： $$ H_i = (H(key)+d_i) \bmod m $$ \(H(key)\)：初始散列地址。第一个发生冲突的关键字位置。

    \(d_i\)：增量序列。发生第 \(i\) 次冲突时，探测地址与初始散列地址的相对偏移量。

    \(m\)：表长

    tips：这里的意思不是说\(H_i\)一次性就定了发生冲突的关键字的位置，而是通过增量序列从初始散列地址逐步探测空闲地址。即，在发生一次冲突后，找这个发生冲突关键字的\(d_1\)增量位置，如果在这个位置已有关键字，则视作发生第二次冲突，对于初始散列地址继续偏移\(d_2\)个地址。即发生冲突后不断尝试偏移量直至找到空闲地址。如果找到\(m-1\)的位置则下一位会从0继续找。

    而当中不定的是增量序列 \(d_i\) 则对于增量序列的取法，影响了处理方法。从而有如下的取法：

    线性探测法

    设计$d_i = i $ 的等差序列。

    优点可以探测全表。但是，往往发生冲突后，对于原不冲突的的关键字产生了影响，使得关键字在相邻散列地址上存在堆积（聚集）降低了查找效率。

    平方探测法

    \(d_i = 0^2,1^2,-(1^2),2^2,-(2^2)…… k^2,-(k^2)\) 其中\(k \le m/2\)

    虽然探测不了全表，但至少探测一半（即使有空位置，却无法插入成功）且相较于线性避免了堆积问题。

    拓展：

    若散列表 \(m\) 可以表示为一个 \(4j+3\) 的素数（7 ， 11， 19），则可以探查所有位置。

    双散列探测法 $$ H_i =(H(key)+i*Hash_2(key))\bmod m $$ 引入了另外一个Hash Table实现了计算增量，具体表现受第二个表影响。

    同样未必能探查所有位置，同平方探测法。调整第二散列表可以实现探测所有的单元。

    若第二散列表计算出来的值与散列表长度互质，可以保证探测所有单元。所以，可以使得散列表长度m为质数，使得其与任何值均互质，实现探测全部单元。

    伪随机序列法

    \(d_i = 伪随机序列\) 可以看作\(d_i = rd.ranint()\)，但并非每次的\(d_i\)都是随机的，对于同一个Hash而言，伪随机序列是固定的，只是其中的每一个值是随机的（毕竟还要查找）。

    而对于以上取法增量序列的取法的相关查找：如果探测到目标关键字则匹配成功。如果探测到空单元，则查找失败。

    关于开放定址法的删除：因为开放定址法的每个关键字地址都由其初始散列地址决定。虽然删除仅需要，查找成功后删除。但删除后直接将单元置空，导致其他关键字无法被查询。因而开放定址法的删除只能进行逻辑删除（即，逻辑上将这个关键字定义被删，但实际关键字仍然占据着存储空间，为查询做准备）

    这导致：开放定址法的散列表虽然被删元素很多，但实际其中都是元素，查找效率仍不会因为删除而提高。需要不定期整理序列

    散列查找的性能分析¶

    计算 失败情况和成功情况下的 \(ASL-Average Search Length\)

    成功情况

    需要得知插入的探测序列 \(i\) 的值，即冲突次数

    有： $$ ASL_{成功} = P*(\sum_j^n (i_j+1)) $$ P基本等于 \(1/n\) 。n为关键字数量，也称作表中记录数。

    失败情况

    不同于成功情况其中P 等于 \(1/m\) 。m为除余的除数。而且累加的数可能要自己一个个试出来。

    填装因子¶

    散列表填装因子 $ a = \frac{表中记录数n}{散列表长度m}$ 其反应了散列表的填充程度。值越大，说明散列表当中的值越满。

    同时也因为散列表越满，其更容易发生冲突，因而导致插入、查找、删除的效率降低。即ASL增加。

    聚集（堆积）现象

    在处理冲突过程中，几个初试散列表地址不同的元素争夺同一个后继列地址的现象。也会导致ASL增加。
