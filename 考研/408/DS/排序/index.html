    Sort¶

    排序算法可分为：内部排序和外部排序。内部排序的数据都在内存中进行排序；而外部排序其产生的背景是，过多的数据无法全部放入内存当中，因而有外部排序。

    其中，内部排序关注如何使得算法的时间复杂度、空间复杂度尽可能地低；而外部排序，还需要关注如何使磁盘的I/O操作尽可能少。

    不稳定排序的定义：如果两个相等的元素在排序后的相对位置与排序前的相对位置不同，则该排序算法是不稳定的。

    插入排序¶

    每次将一个待排序的记录，按其关键字大小插入到已经排序好的子序列中，直至完成。

    C++
    for(int i = 1; i < nums.size(); i++){
    // 如果有序子列的最后一个元素已经比num[i]小了，就没有继续排序的必要了
    if(nums[i-1] > nums[i]){
        int t = nums[i];// 为了方便后移，先提前保存nums[i]的值

        int j; // 这里j要写在循环外，因为cpp有RAII，超出作用域的变量内存会被释放

        // 遍历有序子列，找小于nums[i]的值，并且让所有元素后移。
        for(j = i-1; j >= 0 && nums[j] > t; j--){
            nums[j+1] = nums[j];
        }
        nums[j+1] = t;
        // nums[j]<nums[i]，但是 j+1 的位置的值是要大于的，循环已经帮助我们完成了所有元素后移
    }
}

    整体的思路，就是先判断前面的有序子列是否比 num[i] 小。如果有小，则去一直找比nums[i]大的值或一直找到0。在找的过程中，实现元素后移。最后不满足 for condition 给不满足的值的之后的那个位置赋值nums[i] 。

    分析¶

    空间复杂度： \(O(1)\)

    时间复杂度：\(O(n^2)\)，最好情况是本就有序：\(O(n)\)

    优化¶

    哨兵机制¶
    C++
    for(int i = 2; i < nums.size(); i++){
    if(nums[i-1] > nums[i]){
        nums[0] = nums[i];  //nums[0]就是哨兵
        int j;
        for(j = i-1; nums[j] > nums[0]; j--){ // 减少了j判断是不是>=0;
            nums[j+1] = nums[j];
        }
        // j 是合法值，因为到j才退出，要继续延续j + 1的赋值。
        nums[j+1] = t;
    }
}

    序列空出一个 “0” 下标位置，给nums[i] 进行寄存，这样无需担心j < 0 因为最后到 0 位置，会不满足循环条件退出。相当于上述版本的一个小优化。

    引入折半查找（二分查找）¶

    因为循环中有两个遍历，其中第一个遍历因为序列是未知的，所以较难优化。对于第二个遍历，实际就是查找，其本身遍历的是一组有序子列。那本身遍历的目的就是在有序序列中找target不难想到的是，引入二分查找，来优化第二次遍历查找的速度。

    这里无需引入哨兵，没什么用。本身的作用被二分找位置顺带取缔了。

    C++
    for(int i = 1; i < nums.size(); i++){
    if(nums[i-1] > nums[i]){
        int temp = nums[i];  
        int left = 0, right = i-1;

        // 二分部分
        while(left <= right){
            int mid = left + (right - left)/2;
            if(nums[mid] > temp)
                right = mid - 1;
            else
                left = mid + 1;
        }

        // 这里j取到left的原因是 left+1需要赋值
        // 后移部分
        for(int j = i-1; j >= left ; j--)
            nums[j+1] = nums[j];
        nums[left] = temp;
    }
}

    虽然比原来少比了几次，但是时间复杂度其实仍为 \(O(n^2)\)

    希尔排序¶

    先追求表中元素部分有序，再追求全局有序。意思就是，分割序列成多个子序列，对子序列当中的元素进行直接插入排序。

    子序列应形如：\(L[i,i+d,i+2d……i+kd]\) 这样的结构。通过不断缩小，等于前增量的 \(\frac{1}{2}\) 直至其等于1，最后可以实现原序列有序。

    算法的思想：应该说是灵感，由插入排序可知，对于一个基本有序序列插入排序的效率较高，通过不断提升序列的有序性，进而提高较大规模的序列插排效率。

    C++
    int n = nums.size();
for(int d = n/2; d >= 1; d /= 2){
    for(int i = d; i < n; i++){
        if(nums[i] < nums[i-d]){
            int temp = nums[i];
            int j;
            for(j = i-d; temp < nums[j] && j>=0; j-=d){
                nums[j+d] = nums[j];
            }
            // j 同样是合法值，应该修改 j+d;
            nums[j+d] = temp;
        }
    }
}

    效率和增量\(d\)的取法有关，所以没有确切的时间复杂度

    空间复杂度：\(O(1)\)

    时间复杂度：最坏情况：\(O(n^2)\) 在特定范围可以到达 \(O(n^{1.3})\)

    稳定性：只适用于顺序表，可以随机存取

    交换排序¶

    冒泡排序和快速排序都属于交换排序。即，根据序列中关键字的比较结果交换记录的位置。

    冒泡排序¶

    最ez

    C++
    for(int i = 0; i < nums.size()-1; i++){
    // 加个判断值，如果某轮不发生冒泡则意味着序列已经有序。
    bool flag = false;
    for(int j = i+1; j< nums.size(); j++){  
        if(nums[i] > nums[j]){
            int t = nums[i];
            nums[i] = nums[j];
            nums[j] = t;
            flag = true;
        }
    }
    if (!flag)
        break;
}

    时间复杂度：\(O(n^2)\) 最好情况同样是\(O(n)\)

    空间复杂度：\(O(1)\)

    快速排序¶

    快排实际是一个双指针算法（Double Pointer）以及递归算法。一般采用两个函数构建，一个快排本身，另外一个是作为辅助函数的分区函数。

    C++
    void patition(vector<int>& nums, int left, right){
    int temp = nums[left];
    while(left < right){
        // 找到不符合策略的记录，然后换到符合算法的位置
        // 同时，right停下时正指向这个位置，所以可以给这个right改值（正好是需要改记录的位置）
        while(left < right && nums[right] >= temp) right--; 
        nums[left] = nums[right];
        while(left < rihgt && nums[left] <= temp) left++;
        nums[right] = nums[left];
    }
    nums[left] = temp;
    return left;
}
void quickSort(vector<int> & nums, int start,int end){
    if(start >= end) return;
    int left = partition(nums,start,end);
    quicksort(nums,start,left-1);
    quicksort(nums,left+1,end);
}
    分析¶

    由算法设计课可知，递归算法可以做如下的表达： $$ f(n) = f(\frac{n}{2})+f(\frac{n}{2})+O(n); $$ 可以想象一棵递归树，这里是一棵二叉递归树。最后会把元素数量减少成 1 则有\(n = 2^{h-1} \rightarrow log_2(n) +1= h\)层，一层操作\(O(n)\)

    所以可得时间复杂度为：\(O(nlog_2n)\)

    但最坏的时间复杂度仍然为：\(O(n^2)\)（考虑一个完全逆序或完全有序的数列，其每次分区只能分出一个继续操作的分区）

    而空间复杂度，主要受递归函数导致的栈生长影响，有 \(O(递归层数)\)

    最好空间复杂度-平均复杂度：\(O(log_2n)\)

    最坏空间复杂度：\(O(n)\)

    实际时间复杂度同样受递归层数的影响，具体是一层的操作次数可得 \(n\)（遍历了整个数组，第二层的确单个结点遍历 \(\frac{n}{2}\)，但考虑到两个结点实际还是 \(O(n)\)的复杂度）总层数 × 单个层数的时间复杂度= 总体时间复杂度

    稳定性：不稳定。现在已知的排序算法基本上最高效率也就是\(O(nlog_2n)\)

    对所有尚未确定最终位置的所有元素进行一次处理称作 “一趟”排序，一趟排序需要确定多个元素的最终位置，但一次划分也许只能确定一个元素的位置。所以一趟 跟一次分区并不等同

    简单排序¶

    以按照升序的数列为例。

    C++
    for(int i = 0; i < nums.size()-1; i++){
    // min必须在循环中更新，若正好 i 的位置的记录是最终结果的记录
    // 那min就会停留于一个有序序列的下标，导致下次循环min还在有序序列的下标，反而导致这个位置必定是一个错误的值
    int min = i, j = i;

    for(++j; j < nums.size(); j++){
        if(nums[j] < nums[min]){
            min = j;
        }
    }
    int temp = nums[i];
    nums[i] = nums[min];
    nums[min] = temp;
}

    空间复杂度：\(O(1)\)

    时间复杂度：\(O(n^2)\)

    稳定性：稳定

    链表和顺序表都可以使用简单排序。

    堆排序¶

    堆¶

    概念

    满足下列性质的序列我们称作堆：

    若满足：\(L(i) \ge L(2i)\) 且 \(L(i) \ge L(2i+1)\) ——大根堆（大顶堆）

    若满足：\(L(i) \le L(2i)\) 且 \(L(i) \le L(2i+1)\) ——小根堆（小顶堆）

    利用逻辑结构二叉树理解存储结构堆：

    大根堆：完全二叉树中，根 \(\ge\) 左、右（层次排序，\(2i\)和\(2i+1\)实际都是$ i $的左右孩子结点）

    小根堆：完全二叉树，根 \(\le\) 左、右。

    建立大根堆

    按照顺序存储的完全二叉树中，非终端结点的下标均为 \(i \le \lfloor n/2 \rfloor \ n\)为结点数量（对一个满二叉树，叶结点数 = 非终端结点数 + 1）。

    检查所有非终端结点，是否满足要求。也就是从 \(\lfloor n/2 \rfloor\)开始朝头遍历，让非终端结点和它的左右孩子结点（\(2i、2i+1\)）对比大小，和最大的孩子结点进行交换。但是在这个向上传递的过程中，存在着交换亲子结点后，破坏了子结点和其左右孩子符合堆的特性，则需要对小元素进行下坠。（可以理解为对一个以非终端结点作为子结点的结点来说，我们需要进行循环下坠实现小元素不断下坠）为了使得所有的值都满足要求，大根堆序列的 0 下标应当置空。

    排序部分

    按照选择排序进行排序，不过因为堆自身的性质，堆顶元素一定是最大值，因而可以直接让堆顶元素和待排序列的最后一个元素交换。且为了充分利用大根堆的特性，我们需要在每次交换后将待排序列恢复成大根堆所以有一下过程：

    • 交换堆顶元素和待排序列的最后一个元素。
    • 又因为每次交换一定是堆顶元素，所以可以直接从堆顶元素开始继续跟左右孩子交换构建大根堆。
    • 重复上述过程，直至整个序列有序

    注意一下，上面的逻辑是大根堆，但是为了练习，下面的代码再写的时候是小根堆。只需要改变调整堆处函数的大于和小于即可

    C++
    /** 调整根堆
这个 i 本身也是没必要写的，但是 i 被拆出去了。
实际这个len如果只是为了构建堆是没必要写的，但是为了在排序的时候确定下坠到哪儿为止，所以需要len来确定待排序列长度。
**/
void heapadjust(vector<int> &nums, int i, int len){
    // nums[0]需要空出，因为 0 做不了根。正好做temp使用
    nums[0] = nums[i];

    // 下坠遍历，向下传递
    for (int k = i * 2; k < len; k *= 2){
        // 判断一下用k还是k+1
        if(nums[k] > nums[k+1] && k+1 < len){
            k++;
        }
        // 已经符合了就直接break，因为没有发生交换，不会破坏原先的稳定性
        if(nums[0] < nums[k]){
            break;
        }
        nums[i] = nums[k];
        nums[k] = nums[0];
        // 传递，k值一直做要交换的孩子结点下标，i一直做当前检测的根结点
        i = k;
    }
}
/** BuildHeap
其实可以和调整根堆写成一个函数，但是堆排序你需要不断调整堆
为了写Sort方便，你需要专门将调整堆函数拆除独立为一个辅助函数
**/
void BuildHeap(vector<int> &nums){
    for (int i = (nums.size()-1)/2; i > 0; i--){
        heapadjust(nums, i, nums.size());
    }
}
/** 堆排 
交换，不断调整堆，即为堆排序，正如上面解释一般，每次交换都是根元素，所以需要从根元素开始向下调整
**/
void heapsort(vector<int> &nums){
    for (int i = nums.size()-1; i > 0; i--){
        int temp = nums[1];
        nums[1] = nums[i];
        nums[i] = temp;
        heapadjust(nums, 1, i);
    }
}
    分析¶

    一个结点每次“下坠"只跟自己的左右孩子进行对比，所以下坠一层只需对比2次关键字。若树高为 \(h\) 停留于 \(i\) 层，则每次只需要下坠 \(h-i\) 层，关键字的对比即 \(2(h-i)\) 。而我们已知一个完全二叉树其树高 \(h\) 为 \(h = \lfloor log_{2}n \rfloor + 1\) 或 \(h = \lceil log_2n+1\rceil\)

    推导如下：

    对于一个完全二叉树有 \(n\) 个结点与树高 \(h\)。结点数量为 \(n = 2^0 + 2^1+2^2+2^3……2^{h-1}-m\)

    由等比求和公式我们可以先求得满二叉树的结点数量\(\sum_{i=1}^{h} 2^i = \frac{1-2^h}{1-2} \\\) 可得， $n = \frac{1-2^h}{1-2}\ $

    正如我们前面所说，完全二叉树不一定满，需要考虑 \(m\) 的差值。

    因而有 \(2^{h-1} \le n \le 2^h-1\)

    对前面的不等式则有 \(h\le log_2n+1\)可得\(h=\lfloor log_2n\rfloor +1\)

    而对后面的不等式有 \(log_2(n+1)\le h\)可得\(h=\lceil log_2(n+1) \rceil + 1\)

    因为只有非终端结点需要下坠，所以有： $$ \sum_{i=h-1}^{1}2^{i-1}2(h-i) = \sum_{i=h-1}^{1}2^i(h-i)=\sum_{j=1}^{h-1}2^{h-j}j \le 2n\sum_{j=1}^{h-1}\frac{j}{2^j} \le 4n \first (\le) :log_2(n+1) \le h \le log_2n +1.\ n+1\le 2^h \le 2n \ \ second(\le) :S_{h-1} =\sum_{j=1}^{h-1}\frac{j}{2^j} = \frac{1}{2}+\frac{2}{4}+\frac{3}{8}……+\frac{h-1}{2^{h-1}} \ \frac{1}{2}S_{h-1} = \frac{1}{4}+\frac{2}{8}+\frac{3}{16}……+\frac{h-1}{2^{h}} \ \frac{1}{2}S_{h-1} =\frac{1}{2}+\frac{1}{4}……+\frac{1}{2^{h-1}}-\frac{h-1}{2^h}=(1-\frac{1}{2^{h-1}})-\frac{h-1}{2^h} \ S_{h-1} = (2-\frac{1}{2^{h-2}})-\frac{h-1}{2^{h-1}}=2-\frac{h+1}{2^{h-1}} \当h\rightarrow ∞ 有 S_{h-1} = 2,则S_{h-1}<2 (h \ge 2) $$ 可得：关键字比对不超过 \(4n\)

    建堆的时间复杂度为 \(O(n)\)

    堆排序是直接交换，没有遍历操作，可以只考虑建堆的时间复杂度。下坠一层只需要比较2次，所以不会超过\(O(h) = O(log_2n)\)

    而共有\(n-1\)趟，即调整\(n-1\)个关键字，则有\(O(nlog_2n)\)

    堆排序的时间复杂度：\(O(n)+O(nlog_2n) = O(nlog_2n)\)

    空间复杂度为：\(O(1)\)

    稳定性：不稳定。待排序数组中有重复值，堆排序可能会改变它们的原始相对顺序。

    如果要得到“降序”的序列，可以用小根堆。

    堆的插入删除¶

    插入

    堆本身作为一种存储结构，视作一种完全二叉树的逻辑结构，对于一个插入的新元素。不同于其他的结构通过先通过查找找到应该插入的位置，再进行插入。堆的插入——先插入至末尾作为叶结点，再与其父结点对比是否符合堆的特质，向上传递直至满足或到达根结点。

    其中效率来说，插入只需要跟父结点比，所以一次上升，对比一次。

    删除

    而对于删除元素，则采用用堆底元素替代，在进行堆调整，使其不断下坠，直到条件满足或成为终端结点。

    效率：对于删除来说，删除需要和两个子结点对比，一次下坠需要对比两次。

    归并排序（Merge Sorting）¶

    归并指的是，将多个有序序列合并为一个有序序列。

    算法思想：假设我们有 \(n\)个需要合并的有序序列，则我们用 \(n+1\) 个指针来进行操作。其中\(n\)个指针读取和对比应该插入的数据，而 \(1\) 个指针来确定这个合并的序列需要插入数据的位置。

    而\(m\)个序列，我们需要对比\(m-1\)次。这样的归并我们称为 m路归并

    而对于一个待排序列，我们可以通过递归拆分，实现对一个非有序序列的排序，代码如下：

    C++
    void merge(vector<int> &nums, int low, int mid, int high){
    int *temp = (int *)malloc((high+1) * sizeof(int));
    for (int i = low; i <= high; i++){
        temp[i] = nums[i];
    }
    int i = low, j = mid + 1, k = low; // 写外面，以防止释放内存后置空
    for (i , j , k; i <= mid && j <= high; k++){
        if(temp[i] < temp[j]){
            nums[k] = temp[i];
            i++;
        }else{
            nums[k] = temp[j];
            j++;
        }
    }
    while(i <= mid){
        nums[k] = temp[i];
        k++;
        i++;
    }
    while(j <= high){
        nums[k] = temp[j];
        k++;
        j++;
    }
}

void mergeSort(vector<int> &nums, int low, int high){
    if(low < high){
        int mid = (low + high) / 2;
        // 此处建议改为 int mid = low + (high - low)/2;
        mergeSort(nums, low, mid); 
        mergeSort(nums, mid + 1, high); //采用递归将序列分成多个部分，进行归并排序。
        // 按照此处递归拆分，mergeSort会优先排序最左侧的两个元素，而后是最左侧序列的右半部分以此类推
        // 不断调整后左半部分，而后是右半部分，再是一个更大的左半部分
        merge(nums, low, mid, high);
    }
}

    分析¶

    对于一个归并排序，因为递归，也可得一棵递归树（实际从merge排序的角度来看，实际为一棵倒置的二叉树），递推公式为:\(f(n)= f(n/2)+f(n/2)+O(n)\)

    若觉得不够严谨，可参考\(O\)记法，实际有 \(f(2) = 1\) 不用\(O\)记法一层操作应为\((\frac{n}{2})=O(n)\\\)。

    可知，是一棵 \(h = 2^{h-1}\\\)的二叉树。

    时间复杂度：\(O(nlog_2n)\)

    空间复杂度：\(O(n)\)

    稳定性：稳定

    基数排序¶

    基数排序（Radix Sort）是一种非比较型整数排序算法，通过将整数按位切割成不同的数字，然后按每个位数分别比较排序。适用于整数和定长字符串排序，尤其在数据量大、数值范围小且位数固定时表现优异。因为基数排序不考察代码，这里不给出代码。

    基数排序的过程：

    初始化 \(r\) 个空序列（也就是10个），\(Q_{r-1}\ Q_{r-2} \(。按照**关键字位权重递增次序（个位，十位，百位）**，即先处理个位再逐步递增对**\)d\)个关键字位进行“分配” “收集**”

    分配：顺序扫描各个元素，若当前处理的关键字位 = \(x\) 则将关键字加入序列 \(Q_x\)的队尾。

    收集：按照从\(r-1\)开始递减次序，将关键字依次出队链接。

    分析¶

    因为一趟分配 \(O(n)\) 收集 \(O(r)\)。且有 \(r\) 个序列，有\(d\)趟操作操作有如下：

    时间复杂度：\(O(d(n+r))\)

    空间复杂度：\(O(r)\)

    稳定性：稳定

    擅长解决的场景：

    元素的关键字可以拆分为d组，且d较小。(位数少)

    每组关键字的取值范围较小，即r较小。

    数据元素个数n较大

    计数排序¶

    计数，顾名思义。是统计每个数据出现的次数。而统计数据的这个辅助序列本身是有序的，因而可以利用这个辅助序列和次数，实现对待排序列的排序。

    具体实现：

    • 初始化一个k长的辅助序列，和一个和原序列等长的结果序列。（k是不同的数据的数量）
    • 遍历待排序列的值，将值作为键（key）。在辅助序列中统计每个值出现的次数
    • 再对辅助序列进行操作：将前一个数据出现的次数加到当前数据出现的次数当中。即可得该数据在序列中应当所处的位置
    • 解释：经过第三个操作，辅助序列中的值代表每一个（\(\le key\)）的值累计出现的次数
    • 从后至前遍历原数列，根据在辅助序列当中的统计的值，确定其在结果序列当中的位置。输出一个数据，则辅助序列的值需要减一即给下一个相同数据位置做准备
    • 解释：从后至前可保证相同数据之间的相对位置不变，进而保证稳定。因为通过辅助序列确定位置的方法优先确定位置在后的数据。

    在代码实现上我们可以利用 hash的性质，从而实现统计一个待排序列的数据统计。

    C++
    void CountSort(int A[], int B[], int n, int k) {
    int i;
    int C[k];  // 辅助数组C的长度取决于待排序元素取值范围 [0, k)
    // Step 1: 初始化计数数组
    for (i = 0; i < k; i++) {
        C[i] = 0;
    }
    // Step 2: 统计每个关键字出现的次数
    for (i = 0; i < n; i++) {
        C[A[i]]++;
    }
    // Step 3: 统计小于等于i的元素个数（累计）
    for (i = 1; i < k; i++) {
        C[i] = C[i] + C[i - 1];
    }
    // Step 4: 从后往前遍历原数组，实现稳定排序
    for (i = n - 1; i >= 0; i--) {
        B[C[A[i]] - 1] = A[i];
        C[A[i]]--;
    }
}

    分析¶

    时间复杂度 \(O(n+k)\)

    \(k\)反应的是原数组的值的取值范围——辅助序列长度。

    • 若 \(k=O(n)\)，计数排序的时间复杂度 \(=O(n)\)，此时计数排序的时间效率优于快速排序、堆排序等排序算法的 \(O(nlog_2n)\)
    • 若 \(k>O(nlog2n)\)，计数排序的时间复杂度 \(>O(nlog2n)\)，此时计数排序的时间效率不如快速排序、堆排序等排序算法的 \(O(nlog2n)\)

    空间复杂度 \(O(n+k)\) ——辅助序列和输出序列

    计数排序：用空间换时间，当k足够小则可以考虑计数排序

    稳定性：稳定

    外部排序¶

    排序算法可分为：内部排序和外部排序。内部排序的数据都在内存中进行排序；而外部排序其产生的背景是，过多的数据无法全部放入内存当中，因而有外部排序。

    其中，内部排序关注如何使得算法的时间复杂度、空间复杂度尽可能地低；而外部排序，还需要关注如何使磁盘的I/O操作尽可能少。

    之前我们提及过，对于一个磁盘空间而言。其的I/O基本单位为块。而对于计算机而言，其读写的原理粗略地讲：是通过将外部存储（外存，存储空间，硬盘空间磁盘空间）中的数据（以块的形式）读入内存当中，由CPU进行修改。再写回外存中。

    归并¶

    使用归并算法（merge），可以实现最少用3个块大小的缓冲区（缓存）对任意一个大文件进行排序。其中为一个输出缓存，两个输入缓存。每次读入两个序列进行排序，将排序结果输出回外存中。这种用到\(n\)个块大小的输入缓存，我们可以称为 \(n\) 路归并

    具体实现：

    • 每次读入两个块，进行归并排序。构造初始归并段（让每两个块的数据有序）。若有\(n\)个块，则读取了\(n\)次写了\(n\)次读写共 \(2n\) 次 。
    • 初始归并段是两个块的大小
    • 第一趟归并：每次预备读入两个初始归并段（因为无法全部读入，只能先读入一部分其他做预备读入）。具体来说：优先读入两个归并段的左侧块，归并排序后输出写回外存。一般情况下，输出缓存当中的数据来自两个输入缓存，因而两个输入缓存当中还有数据，我们采用归并将输入缓存当中的最值写进输出缓存。重点：直到某一个输入缓存的数据清空，此时马上读入归并段1的右侧块，填补进空输入缓存。再对这两个输入缓存中的数据使用归并取出数值补入输出缓存（因为本身两个初始归并段已经有序，无需担心补入的数据会把当前输出块的数据换出）重复上述过程：
    • 输入缓存清空 \(\rightarrow\) 读入新块 \(\rightarrow\) 归并补写。
    • 重复第一趟归并的过程，不同的是每次预备读入的两个归并段，皆为上次归并产生的新归并段。

    注意，除了第一次构建初始归并段采用的是归并排序，实际其他归并过程采用的归并是内部归并，只是利用了归并的方法而非直接归并排序。

    外部排序时间 = 读写时间（占大头） + 归并排序时间 + 内部归并时间

    而读写时间受读写次数影响，读写次数 = \(2n\) + \(2n\)*归并趟数。（前一个\(2n\)为初始化归并段，读入两个块，写回两个块。后一个\(2n\)是每趟归并所做的操作）

    因而，我们可以尽可能减少归并趟数实现优化外部排序。

    优化¶

    多路归并¶

    即原先仅用了两个输入缓冲区进行归并，现在采用三个、四个、八个或更多输入缓冲区进行归并。每一次就可以操作和产生更大的归并段，从而实现减少趟数，减少读写次数进而减少时间。

    对 \(r\) 个初始归并段，做\(k\)路归并，可以用归并树表示（倒置的一棵\(k\)叉树）。若树高为 \(h\) ，则有\(k^{h-1} \ge r\) \(\rightarrow\) \(h-1 = \lceil log_kr \rceil = 归并趟数\)

    通过等式，可以得：k越大，r越小，则归并趟数越少。

    劣势¶
    1. 内存开销增大
    2. 因为有多个输入缓存进行对比，归并的对比次数增加，则内部归并所需时间增加
    减少初始归并段的数量¶

    也是需要多路归并。不多做解释，参考上述的\(r\)越小。实际就是增长初始归并段的长度

    额外

    k路平衡归并，并非算法，而是一种特殊的归并，满足下列性质即为 k路平衡归并：

    • 最多只有k个段并为一个
    • 每一趟归并当中，若有m个归并段参与归并，则经过一趟处理可以得到 $\lceil m/k\rceil $

    败者树¶

    即，在每个结点，两个数据之间进行对比对于更符合条件的数据向上传递进父结点继续进行对比，直至仅剩一个数据。整个树形如一个根结点下接入一个完全二叉树（k没有限制，虽然常用2的幂次，但实际上任意取所以是一棵完全二叉树）。

    Text Only
                                  *
                              |
                              *
                            /   \
                           *     *
                          / \   / \
                         *   * *   *

    其中，k个叶结点是参与对比的元素，非叶结点则记录了左右子树中的“败者”所在的归并段关键字（来自哪一个归并段）。

    之前的内容中提及多路平衡导致，归并的对比次数增加。而败者树可以帮助我们减少归并的对比次数。

    具体如下

    • 共有r个归并段，每次取其中的 k个（k个输入缓存）参与败者树，我们各取其中的最值，得出一个全关键字的最值，记录其归并段。
    • 取出这个这个最值后，最值所在的归并段补上其下一个关键字。
    • 仅有这个新关键字所在的子树需要向上传递（进行关键字对比），直至比出一个新的全关键字最值

    以下讨论不考虑完全二叉树最上端结点，因为其层没有任何关键字对比

    对于 k路归并，第一次构造败者树需要进行 \(k-1\)次对比（等比数列求和，\(\sum_{i=1}^{h-1}\frac{k}{2^{i}}=\frac{1-2^{h-1}}{1-2}=2^{h-1}-1\ \ \ (k = 2^{h-1})\\\)）。而后只需对比$\lceil log_2k \rceil $ 次关键字便可得到最值。

    推导：对于完全二叉树。其在h层的结点数量 \(n \le 2^{h-1}\) ，则对于叶结点有 \(k \le 2^{h-1}\) 可得\(h-1\ge log_2{k}\)

    \(h-1 =\lceil log_2 k\rceil\) ，因为叶结点层不参与对比所以得对比 \(\lceil log_2 k\rceil\)次

    可见，通过构建败者树，我们的k路归并，从原先的k-1次对比降为了 \(\lceil log_2k\rceil\)次对比。

    代码实现思想¶

    只需定义一个k长的数组，记录非终端结点的归并段编号。

    置换-选择排序¶

    实现减少 \(r\) 来减少读写时间，提高效率的算法。

    常规方法下：初始归并段数量 \(r = n/l\) 其中，\(n\)为外存中的记录，\(l\)为内存工作区WA中可以容纳的记录。

    实现思想（以升序为例）：

    • WA读入数据（关键字），取 \(l\) 条记录中d的一个最小值放入归并段。并记录这个值（以下称temp）。王道中称：MINIMAX
    • 此时 WA 中未满，再读入一条记录（数据），与temp对比，取大于temp数据的最小值放入归并段，并更新temp
    • 重复第二个过程，直至WA中的每一个数据均无法再放入归并段中（即WA中的每一个数据都比temp要小）
    • 则当前构造的归并段构造结束，开始构造下一个归并段，重复上述过程。

    使用置换-选择排序，实现了初始归并段数量不受WA中 \(l\) 的限制，尽可能减少 r 的值。（归并段不等长）

    最佳归并树¶

    由置换-选择排序构建的归并段并不等长，如果我们尝试对几个不等长的归并段进行二路归并，可以构建出一个归并树

    而这棵归并树的带权路径长度WPL应和这几个归并段进行归并所需要的读次数和写次数相同

    即有：WPL*2= 磁盘I/O次数

    构建二路最佳归并树¶

    二路最佳归并树：每次取归并段长度最小的两个归并段进行合并，合并为一个新的归并段。再从现有的归并段中（包括新归并段）取最短的两个归并段进行合并。

    则可以得到一个最佳归并树，其读写次数应是最小的组合（本质上，是只重复较短归并段的反复读写，如果用随机的方式进行读写，总会有一个较长的归并段从始至终进行读写操作，造成冗余）

    构建多路最佳归并树——构造k叉哈夫曼树¶

    而对于多路归并（k > 2）一般会出现，最后一次参与归并的归并段数量 < k 的情况。导致无法做到最佳。针对这种情况，我们可以引入几个长度为 0的“虚段”。再进行 k 叉哈夫曼树的构造。

    具体是几个，需要判断：k叉最佳树一定是一棵严格 k 叉树——结点度为 k 或 0，即非终端结点一定有k个孩子结点。参考树章节内容：则结点数量 \(n = k*n_k+1=n_0+n_k\) ，前者是计算所有非终端结点的孩子的数量+根结点，后者是单纯相等。

    而我们可知 \(n_0\)即为归并段总数 \(r\)，则构建一个哈夫曼树需要满足如下等式：

    \((k-1)*n_k=n_0-1 \rightarrow n_k = \frac{n_0-1}{k-1}\\\)

    即，归并段总数-1可以被 多路的\(k-1\)所整除。

    若 \(r-1\) 可以被 \(k-1\)整除，则不用补充虚段。

    若 \(r-1\) 可以被 \(k-1\)整除，则有 \((r-1) \bmod (k-1) = u\)，意味着多出来 \(u\) 个，则需要补充 \(k-1-u\)个
